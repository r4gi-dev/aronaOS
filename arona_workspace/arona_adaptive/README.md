# arona_adaptive

AronaOS 適応層(信頼モデル)の骨組み実装。

実装計画(設計まとめドキュメント「27. 具体的な実装計画」)の順序5に対応する。
権限システム・Guardianとは別の、日常的なやり取り全般における信頼度を管理する
(設計まとめ 12章)。

## 構成

| ファイル | 役割 |
|---|---|
| `src/schema.rs` | 承認の仕方(`ApprovalManner`)・信頼スコア(`TrustScore`)のスキーマ |
| `src/engine.rs` | 信頼モデル本体(`TrustModel`)。カテゴリ単位のスコア管理・確認要否の判定 |
| `src/audit.rs` | 信頼スコアの変化をアロナ記憶へ記録する監査ログ |

## 設計まとめドキュメントとの対応

- **カテゴリ単位の粒度**: `TrustCategory`は文字列ベース(閉じたenumにしていない)。
  単一の総合スコアにすると信頼の飛躍(ファイル整理の実績がネットワーク設定にまで
  波及する等)が起きるため採用しなかった、という設計まとめの判断をテスト
  (`カテゴリ間で信頼は波及しない`)でも直接検証している
- **基礎スコア+補正の3層構造**: `record_approval()`が`ApprovalManner`(即決/迷った末)の
  重み付きで`weighted_approval_count`を積み上げる。即決は満点(1.0)、迷った末のOKは
  半分の重み(0.5)としており、「渋々OKした行動は信頼スコアが伸びにくい」という
  設計まとめの方針をそのまま実装している
- **即時反映**: `declare_no_confirmation_needed()`が蓄積スコアに関係なく即座に
  確認不要へ切り替える

## 現時点でスタブになっている部分(今後の課題)

- しきい値(`CONFIRMATION_SKIP_THRESHOLD`)は固定値。実運用でのチューニングが必要
- `ApprovalManner`(即決か迷った末か)の実際の判定方法(ユーザーの応答速度・
  言い淀みの検出など)は未実装。現状は呼び出し側が明示的に渡す前提
- Guardian・権限システムとの実際の接続(信頼スコアを見て確認をスキップする
  呼び出し元)は未実装
- 時間経過による信頼スコアの減衰は未実装。記憶層の「想起しやすさ」のような
  忘却曲線を信頼スコアにも適用すべきか、設計まとめには明記がなく今後の検討事項
